# OpenSpec Project Configuration Remediation Plan

> Execute this plan on branch `peer-inbox-bridge`. Preserve the unrelated
> `.agent/` tree and the pre-existing Herdr inbox test edit.

## Goal

Replace the generic `openspec/config.yaml` template with repository-specific,
source-backed guidance for the whole CLI Agent Orchestrator project, and revise
the design document so it addresses every blocking Claude and Agy finding.

## Task 1: Revise the design contract

**Files**

- Modify: `docs/superpowers/specs/2026-07-22-openspec-project-config-design.md`

**Steps**

1. Split the control-plane description into:
   - HTTP API as the inbound shared boundary for external clients.
   - `cao-ops-mcp-server` as the external operations plane that calls HTTP.
   - `cao-mcp-server` as the in-session orchestration plane, including its
     intentionally local/direct service paths.
   - WebSocket PTY streaming as a localhost-only, unauthenticated surface whose
     exposure risk must be analyzed explicitly.
2. State that `cao:write` and `cao:admin` are fleet-wide authority, not
   per-session capabilities.
3. Distinguish real launchable providers, the launchable test-only
   `mock_cli`, and persistence-only `peer`.
4. Record tmux as the stable default backend and Herdr as experimental.
5. Scope compatibility to named public HTTP/MCP/CLI/serialized-data surfaces,
   with explicit migration requirements instead of an unlimited promise.
6. Require default-off compatibility analysis for authentication and telemetry.
7. Expand quality gates to match CI: Python non-E2E suite, web build, MCP Apps
   typecheck/tests/build/`scan:jit`/size/HTTP-boundary/coverage, Black, isort,
   no new mypy errors, Markdown links, gitleaks, and PII-safe fixtures.
8. Correct drift ownership:
   - `src/` and `pyproject.toml` own runtime/tool configuration.
   - root `skills/` is canonical and package mirrors are generated by
     `scripts/sync_skills.py --check`.
   - database schema changes use the migration ownership in
     `clients/database.py`.
9. Make OpenSpec verification concrete with the installed CLI command and
   explain that Markdown-link validation only sees tracked files.

## Task 2: Replace the generic OpenSpec template

**Files**

- Modify: `openspec/config.yaml`

**Steps**

1. Keep `schema: spec-driven`.
2. Add a YAML block-scalar `context` capped at roughly 1,200 words.
3. Encode only stable repository facts and link volatile inventories to their
   canonical source files.
4. Add artifact rules for `proposal`, `spec`, `design`, and `tasks`.
5. Require proposals to identify affected control planes, providers/backends,
   compatibility/migration, authorization/privacy, observability, and non-goals.
6. Require specifications to state normative, testable success and failure
   behavior, including cursor progression, acknowledgement ownership,
   idempotency, retry, cancellation, timeout, and partial failure when relevant.
7. Require designs to identify the authoritative mechanism versus supplemental
   wakeups, task lifecycle, data ownership, and cross-plane error mapping.
8. Require tasks to use tests-first ordering and current project gates without
   inventing new linters or treating existing non-blocking mypy as a green gate.

## Task 3: Validate the configuration and documentation

**Commands**

1. Parse and inspect the YAML:

   ```bash
   uv run python -c 'from pathlib import Path; import yaml; data=yaml.safe_load(Path("openspec/config.yaml").read_text()); assert data["schema"] == "spec-driven"; assert isinstance(data["context"], str); assert set(data["rules"]) == {"proposal", "spec", "design", "tasks"}'
   ```

2. Validate OpenSpec artifacts:

   ```bash
   openspec validate --all --strict --json
   ```

3. Stage only the new documentation before running the tracked-file link
   checker, then unstage without discarding content:

   ```bash
   git add openspec/config.yaml docs/superpowers/specs/2026-07-22-openspec-project-config-design.md docs/superpowers/plans/2026-07-23-openspec-project-config-remediation.md
   uv run python scripts/validate_markdown_links.py
   git restore --staged openspec/config.yaml docs/superpowers/specs/2026-07-22-openspec-project-config-design.md docs/superpowers/plans/2026-07-23-openspec-project-config-remediation.md
   ```

4. Run:

   ```bash
   git diff --check
   ```
